# Spec: 02-db

**Goal:** Supabase schema + typed data access for manuals, steps, and the jobs queue.
**Package/app(s):** `packages/db`.
**Depends on:** 01-core.

## Inputs

- `@vitruvius/core` types and zod schemas.
- Env: `PUBLIC_SUPABASE_URL`, `PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.

## Outputs

- A SQL migration creating `manuals`, `steps`, and `jobs` tables matching
  `InstructionManual` / `ManualStep` / `Job`.
- A typed Supabase client and CRUD query functions.
- Row⇄type mappers validated with the core zod schemas.
- Queue helpers: `enqueueJob`, `claimNextJob`, `completeJob`, `failJob`.

## In scope

- The migration and table definitions.
- Typed client + CRUD for manuals/steps.
- `claimNextJob` using `SELECT ... FOR UPDATE SKIP LOCKED` so claiming is concurrency-safe.
- Validating rows against the core schemas at the boundary.

## Out of scope

- Auth UI.
- Storage upload logic (that lives in the web upload slice / engine).
- Any AI or media processing.

## Acceptance criteria

- The migration applies cleanly.
- Query + queue functions typecheck against the core types.
- Two concurrent `claimNextJob` calls never claim the same job.

## Validation

- `pnpm --filter @vitruvius/db typecheck`
- `pnpm --filter @vitruvius/db lint`
- Apply the migration against a local/dev Supabase and exercise the queue helpers.
